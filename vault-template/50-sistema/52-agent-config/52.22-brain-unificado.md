# Arquitetura Unificada de Memória — Obsidian + [FERRAMENTA]

> ⚠️ **ATUALIZADO 2026-09-19** — [FERRAMENTA] removido; a camada de recall agora é **obsidian-kb** ([[52.25-obsidian-kb-operacao]]). O mapeamento abaixo é histórico; o princípio permanece: **vault = fonte de verdade, camada de recall = índice descartável**.

> Sistema integrado de memória do ecossistema Hermes/OpenCode.  
> **Última revisão:** 2026-09-11 (consolidação após investigação dos agentes de pesquisa).

## Visão geral

O sistema de memória opera com **duas camadas complementares** que trabalham juntas, não de forma redundante:

| Camada | Sistema | Função | Domínio | Quando usar |
|---|---|---|---|---|
| **Conhecimento** | Obsidian Vault (`%OBSIDIAN_VAULT_PATH%`) | Fonte de verdade, estrutura, edição humana | Decisões, specs, tasks, contexto estruturado, kanban, MOCs | Leitura humano, edição, navegação |
| **Contexto** | [FERRAMENTA] (`viking://`) | Recuperação semântica eficiente | L0/L1/L2 tiers, busca vetorial, contexto de agente | Recuperação por agentes, economia de tokens |

### Princípio central

- **Obsidian** = onde o conhecimento **mora** (estrutura, edição, persistência)
- **[FERRAMENTA]** = como o agente **recupera** esse conhecimento (semântica, L0/L1/L2, economia de tokens)

**O agente não substitui um com o outro — ele usa os dois em sequência.**

## Arquitetura de recuperação (Agente)

```mermaid
flowchart LR
    A[Agente] --> B{Precisa de contexto?}
    B -->|Sim| C[[OpenViking]]
    C --> D[L0: 100 tokens<br/>Relevância?]
    D -->|Sim| E[L1: 2.000 tokens<br/>Informação suficiente?]
    E -->|Sim| F[Usa L1]
    E -->|Não| G[L2: Nota inteira<br/>Obsidian]
    F --> H[Agir]
    G --> H
    D -->|Não| H
    B -->|Não| H
    H --> I[Escrever/Atualizar]
    I --> J[Obsidian]
    J --> K[[FERRAMENTA] re-indexa]
```

### Exemplo real (fluxo do agente)

1. **Hermes** precisa entender a decisão de arquitetura do WOD
2. **[FERRAMENTA]** retorna L0: "Decisão de usar Next.js 16 + Prisma 7 + Supabase, votada em 2026-09-09"
3. **Hermes** decide que precisa do L1 para mais detalhes
4. **[FERRAMENTA]** retorna L1: resumo estruturado da decisão (motivação, opções consideradas, resultado)
5. **Hermes** precisa ver a spec completa → lê a nota no **Obsidian** (L2)
6. **Hermes** escreve atualização → salva no **Obsidian**
7. **[FERRAMENTA]** detecta mudança e re-indexa automaticamente

## Integração técnica

### Configuração do [FERRAMENTA]

```bash
# Instalação
pip install [ferramenta] --upgrade

# Inicialização (wizard interativo)
[ferramenta]-server init
# → Escolher provider: Ollama (local) ou OpenRouter (cloud)
# → Escolher embedding: local ou remote
# → Configurar path do vault: %OBSIDIAN_VAULT_PATH%

# Validação
[ferramenta]-server doctor

# Início do servidor
[ferramenta]-server
```

### Sincronização Obsidian → [FERRAMENTA]

O [FERRAMENTA] monitora o vault Obsidian automaticamente:

1. **Detecta mudança** em `%OBSIDIAN_VAULT_PATH%\`
2. **Processa em tiers:** L0 (resumo), L1 (overview), L2 (conteúdo integral)
3. **Atualiza índices** vetoriais
4. **Preserva trajetória** (observable retrieval)

### Integração com Hermes

- **Hermes** usa [FERRAMENTA] como MCP server (integração oficial)
- **Hermes** lê/escreve no Obsidian via `obsidian-vault` e `obsidian-doc-sync`
- **[FERRAMENTA]** é o "acelerador" de contexto — Hermes pergunta pro [FERRAMENTA] antes de ler o Obsidian

### Integração com OpenCode

- **OpenCode** usa [FERRAMENTA] como MCP server (integração oficial)
- **OpenCode** lê/escreve no Obsidian via `obsidian-vault`
- **OpenCode** usa [FERRAMENTA] pra recuperar contexto entre sessões

## Comparação: [FERRAMENTA] vs Smart Connections

| Critério | Smart Connections | [FERRAMENTA] | Vencedor |
|---|---|---|---|
| **Busca semântica** | ✅ Por significado | ✅ Por significado | Empate |
| **Tokens gastos** | ❌ Arquivo inteiro | ✅ L0=100, L1=2k, L2 sob demanda | **[FERRAMENTA]** |
| **Estrutura** | ✅ Usa tags/links do Obsidian | ❌ Filesystem separado | **Smart Connections** |
| **Estado** | ✅ Kanban, MOCs, Context Packs | ❌ Só memória/recursos | **Smart Connections** |
| **Edição humana** | ✅ Direto no Obsidian | ❌ Via agente | **Smart Connections** |
| **Agente-friendly** | ❌ Carrega tudo | ✅ Tiers, budget-aware | **[FERRAMENTA]** |
| **Observable retrieval** | ❌ Black-box | ✅ Trajetória visível | **[FERRAMENTA]** |
| **Multi-agente** | ❌ Um agente por vez | ✅ Integração oficial Hermes/OpenCode | **[FERRAMENTA]** |

**Conclusão:** Os dois são complementares. Usar **Smart Connections** pra edição/navegação humana e **[FERRAMENTA]** pra recuperação por agentes.

## Migração: gbrain → [FERRAMENTA]

### O que muda

| Antes (gbrain) | Depois ([FERRAMENTA] + Obsidian) |
|---|---|
| `gbrain doctor` | `[ferramenta]-server doctor` |
| `gbrain put "texto"` | [FERRAMENTA] auto-indexa Obsidian |
| `gbrain search "query"` | `ov find "query"` ou via MCP |
| `gbrain delete` | [FERRAMENTA] gerencia automaticamente |
| PGLite local | [FERRAMENTA] (pode usar Ollama local) |
| Busca simples | L0/L1/L2 tiers + directory recursive retrieval |

### Plano de migração

1. **Instalar [FERRAMENTA]** e configurar provider (Ollama local ou OpenRouter)
2. **Indexar vault** Obsidian no [FERRAMENTA] (apontar para `%OBSIDIAN_VAULT_PATH%`)
3. **Registrar como MCP** no Hermes e OpenCode
4. **Testar buscas** comparando gbrain vs [FERRAMENTA]
5. **Remover gbrain** dos docs/skills/boards (limpar referências)
6. **Desinstalar gbrain** CLI

### O que fazer com o gbrain

- **Desinstalar** o gbrain CLI (`pip uninstall gbrain` ou equivalente)
- **Remover skills** `setup-gbrain.md` e `sync-gbrain.md` de `50-sistema/52-agent-config/Skills/`
- **Atualizar docs** que mencionam gbrain (Metodo de Trabalho, Agent Identity, etc.)
- **Arquivar** histórico de decisões do gbrain (manter no 90-arquivo se relevante)

## Papéis atualizados (pós-migração)

### Hermes (orquestrador)
- **Lê:** [FERRAMENTA] (recuperação semântica) + Obsidian (notas específicas)
- **Escreve:** Obsidian (decisões, specs, handoffs) → [FERRAMENTA] re-indexa
- **Não escreve:** Código

### OpenCode (executor)
- **Lê:** [FERRAMENTA] (contexto entre sessões) + Obsidian (Context Pack, Handoff)
- **Escreve:** Obsidian (progresso, evidências) → [FERRAMENTA] re-indexa
- **Não decide:** Escopo

### Obsidian (conhecimento)
- **É:** Fonte de verdade, estrutura, edição humana
- **Não é:** Motor de busca semântico (isso é do [FERRAMENTA])

### [FERRAMENTA] (contexto)
- **É:** Motor de recuperação semântica, economia de tokens, contexto de agente
- **Não é:** Fonte de verdade (isso é do Obsidian)
