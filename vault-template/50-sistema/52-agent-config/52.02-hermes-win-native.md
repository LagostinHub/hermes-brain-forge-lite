## Autostart Windows (sem admin)

### Camadas ativas
| Camada | Trigger | Quem | Status |
|---|---|---|---|
| **Shell:Startup** | logon user | `Hermes_Start.vbs` | ✅ instalado |
| **Task `HermesGatewayAtLogOn`** | logon user | `wscript.exe Hermes_Start.vbs` | ✅ user-owned (<DOMAIN>\<user>) |
| **Task `HermesGatewayWatchdog_v2`** | DDI 1 min | `hermes-watchdog.cmd` | ✅ user-owned |
| **Task `HermesGatewayAtStartup`** | boot PC | - | ❌ falha (precisa admin) |

### Cobertura efetiva
- **Logon usuário**: `HermesGatewayAtLogOn` ✅ + Shell:Startup\Hermes_Start.vbs ✅
- **Boot sem logon**: dependemos da `Hermes_Gateway` legacy task (noop.cmd), que permite spawn benigno
- **Crash loop**: `HermesGatewayWatchdog_v2` monitora :8642 e reinicia via venv se cair (1 min heartbeat)

### Source de verdade
- `AppData\Local\hermes\bin\hermes-autostart.ps1` — PROJETO canonico do boot
- v1 da fase final (24/07/2026) **substitui** completamente o Hermes_Gateway.cmd/vbs original

## Decisões técnicas (não voltar atrás)

1. **Python 3.11 venv** é o **único** interpreter para gateway. Substitui miniconda 3.14 e uv-python 3.11 — ambos causavam disjoint lock.
2. **Python 3.14 (miniconda3) uninstalled**: pip uninstall hermes-agent 0.15.2 + 5 PATH entries removidas do User PATH. (System PATH HKLM ainda tem residual, mas não é usado por nenhum task nosso.)
3. **Plugin heartbeat desativado** (4 listas em `config.yaml`) — usa `fcntl` (POSIX-only), quebra em Windows.
4. **`terminal.modal_mode`** = `never` (locks-out Docker/Singularity/Modal fallback).
5. **`terminal.auto_source_bashrc`** = `false`.
6. **Hermes-agent pypi 0.19.0** em venv Python 3.11, git HEAD=`af250d8` em `AppData\Local\hermes\hermes-agent`.
7. **Omniroute** NÃO é mais usado (deprecado 2026-09-09).
8. **Skills.sh** (`vercel-labs/skills`) é a fonte oficial de skills de terceiros via `npx skills add <owner/repo> --copy -y`.
9. **Skipped-up 2x duplicate Python** via unificação em single venv.

## Como diagnosticar

### Estado rápido
```powershell
# Gateway alive?
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -match 'hermes_cli.main.*gateway run' } |
  Select ProcessId, Name, @{n='Py';e={$_.ExecutablePath}}

# Watchdog + logon tasks
Get-ScheduledTask | Where-Object { $_.TaskName -match "hermes" }

# Logs (last 30 lines)
Get-Content "%USERPROFILE%\AppData\Local\hermes\logs\gateway.log" -Tail 30
```

### Reiniciar gateway limpo (zero stale state)
```powershell
$procs = Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -match 'hermes_cli.main.*gateway run' -and $_.CommandLine -notmatch "stop|status" }
foreach ($p in $procs) { Stop-Process -Id $p.ProcessId -Force -ErrorAction SilentlyContinue }

Remove-Item "%USERPROFILE%\AppData\Local\hermes\gateway.lock" -Force -ErrorAction SilentlyContinue
Remove-Item "%USERPROFILE%\AppData\Local\hermes\gateway.pid"  -Force -ErrorAction SilentlyContinue

# So sub gateway — usa venv 3.11 (unico qualified interpreter)
Start-Process -FilePath "%USERPROFILE%\AppData\Local\hermes\hermes-agent\venv\Scripts\pythonw.exe" `
  -ArgumentList "-m","hermes_cli.main","gateway","run" `
  -WorkingDirectory "%USERPROFILE%\AppData\Local\hermes" `
  -WindowStyle Hidden
```

### Boot from cold (sim reboot)
```powershell
wscript.exe "%USERPROFILE%\AppData\Local\hermes\bin\Hermes_Start.vbs"
# vbs calls hermes-start.cmd → powershell → hermes-autostart.ps1
# ps1 inicia o gateway
```
