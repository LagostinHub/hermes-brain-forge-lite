### Operating Model (Hermes / OpenCode)
- **Hermes** (orquestrador/zelador): planeja, escreve Handoff, analisa (`code-review`), nunca escreve código.
- **OpenCode** (executor): recebe Handoff, ordena plano, builda, devolve; nunca decide escopo.
- Loop: `Handoff → Ordena Plano → Build → Análise → (nova rodada | Done | Blocked)`.
- Skills por papel: Hermes usa `spec`/`grill-me`/`to-tickets`/`writing-plans`/`plan-eng-review`/`code-review`/`learn`; OpenCode usa `writing-plans`/`implement`/`tdd`/`subagent-driven-development`/`git-commit`. Combos A(Spec→Plan) B(Decompose→Parallel) C(Build→Verify) D(Close→Learn).

### Para o Hermes Usar Isso
1. Ler `Mapa.md` → MOC raiz que conecta os 8 projetos ativos.
2. Ler `Dashboard.md` → estado ao vivo (abre sozinho no Obsidian).
3. Ler `Context Pack.md` do projeto alvo → estado + pendências + como continuar.
4. Ler `agent-config/Metodo de Trabalho.md` → regras do contrato.
5. Escrever o Handoff e despachar ao OpenCode; nunca codar direto.
6. Ao receber a entrega, rodar `code-review` e decidir próxima rodada / Done / Blocked.
